    코드 리뷰: train_seg_cell_opti.py¶

    rfdetr/src/rfdetr 구조와 train_seg_cell_opti.py를 비교한 코드 리뷰입니다.

    1. 결론 요약¶

    항목 문제 권장
    wandb 스크립트에서 wandb.init() 호출 + rfdetr 내부에서도 MetricsWandBSink가 wandb.init() 호출 → 이중 초기화 스크립트에서는 wandb.init 하지 말고, model.train(wandb=True, project=..., run=...) 만 넘겨서 config 한 곳에서만 처리
    train 인자 train_ann_file, val_ann_file, resolution 등은 TrainConfig에 없는 필드 → 무시됨 dataset_dir, output_dir, epochs, batch_size, grad_accum_steps, lr, resume, early_stopping, wandb, project, run 등 TrainConfig/SegmentationTrainConfig 필드만 전달
    resolution resolution은 TrainConfig가 아니라 모델 config(RFDETRSegMediumConfig 등)에 있음. train() 인자로 넘겨도 반영 안 됨 모델 사이즈 선택(SegSmall / SegMedium 등)으로만 해상도 결정. resolution 인자는 train()에서 제거
    class_names / num_classes roboflow 모드에서는 train_from_config 안에서 _load_classes(dataset_dir)로 데이터셋에서 자동 로드 → 스크립트에서 준 값은 학습 시 덮어씌워짐 데이터셋이 이미 올바르면 스크립트에서 굳이 넘기지 않아도 됨 (모델 생성 시점용으로만 유지 가능)
    Artifact 업로드 학습 끝난 뒤 wandb.log_artifact() 호출하는데, rfdetr이 on_train_end에서 wandb.finish()를 호출한 이후라 run이 이미 종료됨 → artifact가 기대한 run에 붙지 않을 수 있음 artifact는 제거하거나, rfdetr 쪽에 on_train_end 콜백으로 넣는 식으로 한 run 안에서 처리

    2. rfdetr 학습/설정 흐름¶

    2.1 model.train(**kwargs) 진입¶

    detr.py:
  train(**kwargs)
    → config = self.get_train_config(**kwargs)   # kwargs → SegmentationTrainConfig
    → self.train_from_config(config, **kwargs)
    • train()에 넣은 kwargs는 전부 get_train_config(**kwargs)로 전달되고, 그 결과가 SegmentationTrainConfig(**kwargs)로 만들어짐.
    • 따라서 TrainConfig / SegmentationTrainConfig에 없는 키는 Pydantic에서 무시되거나 에러가 나며, resolution / train_ann_file / val_ann_file 같은 건 config에 없으므로 의미 없음.

    2.2 Config에 이미 있는 것들¶

    rfdetr/config.py의 TrainConfig (및 SegmentationTrainConfig)에는 이미 다음이 정의되어 있음:

    • dataset_dir, output_dir, epochs, batch_size, grad_accum_steps, lr, resume
    • early_stopping, early_stopping_patience, early_stopping_min_delta, early_stopping_use_ema
    • wandb: bool = True, project, run
    • tensorboard, class_names, dataset_file, …

    즉 wandb 사용 여부·프로젝트·run 이름은 이미 config 단에서 다 정의되어 있고, train_from_config() 안에서 이렇게 사용됨:

    # detr.py train_from_config()
if config.wandb:
    metrics_wandb_sink = MetricsWandBSink(
        output_dir=config.output_dir,
        project=config.project,
        run=config.run,
        config=config.model_dump()
    )

    그리고 MetricsWandBSink 생성자 안에서 이미 wandb.init(project=..., name=run, config=config, ...) 를 호출함 (util/metrics.py).
    따라서 스크립트에서 한 번 더 wandb.init()를 호출하면 이중 초기화가 되고, run/프로젝트가 두 군데서 설정될 수 있어 혼란과 중복이 생김.

    3. 스크립트에서 넘기면 안 되거나 무시되는 인자¶

    스크립트 인자 TrainConfig 여부 비고
    train_ann_file ❌ 없음 roboflow는 dataset_dir만 있으면 train/_annotations.coco.json 등 경로 고정. 무시됨
    val_ann_file ❌ 없음 동일. 무시됨
    resolution ❌ 없음 해상도는 모델 config(예: RFDETRSegMediumConfig.resolution)에만 있음. train()에 넣어도 반영 안 됨

    해상도를 바꾸고 싶다면 모델 크기(RFDETRSegSmall vs RFDETRSegMedium 등)를 바꾸는 수밖에 없고, train()에 resolution=를 넘기는 건 효과 없음.

    4. 권장 작성 방식¶

    • wandb: 스크립트에서 wandb.init() 호출 제거.
      model.train(..., wandb=True, project="cell_rfdetr", run=run_name) 처럼 config 경로로만 넘기면, rfdetr이 한 번만 init하고 메트릭까지 동일 run에 로깅함.
    • train() 인자: dataset_dir, output_dir, epochs, batch_size, grad_accum_steps, lr, resume, early_stopping, wandb, project, run 등 TrainConfig에 실제로 있는 필드만 넘기기.
    • resolution / size: train() 인자에서 제거하고, 모델 클래스 선택(예: --size S → RFDETRSegSmall, --size M → RFDETRSegMedium)으로만 해상도 간접 선택.
    • sanity check, output_dir 타임스탬프, GPU cleanup 등은 스크립트에 두어도 됨.
      다만 best checkpoint artifact는 run이 이미 끝난 뒤에 올리면 run과 연결이 안 되므로, 필요하면 rfdetr 콜백으로 넣거나 제거하는 편이 정리하기 좋음.

    이렇게 하면 config 한 곳에서만 wandb·학습 인자가 정의되고, 스크립트는 “어떤 데이터/출력/run 이름으로 학습할지”만 정해 주는 역할로 맞출 수 있어 중복이 사라짐.
